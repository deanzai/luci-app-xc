# XC 内核资源更新设计

## 目标

在现有“Xray core”页签内增加 Xray 核心、GeoIP、GeoSite 的独立更新入口。更新源只从内置默认下载源中选择，不提供自定义 URL；点击更新后直接下载并替换目标资源，不执行内容、版本或哈希校验，同时保留一份初始默认资源作为回滚基础。

## 用户确认的边界

- “多个默认路径”指多个内置下载源 URL/镜像，不是本地保存目录。
- 页面不再显示或保存自定义下载地址。
- 每个资源单独选择下载源、单独点击更新。
- 更新流程不验证下载内容是否为正确的 Xray 核心或 Geo 数据。
- 第一次更新前保存当前资源的一份默认快照；后续更新不覆盖该快照。
- 现有 Xray 核心上传、激活、回滚流程继续保留。

## 交互设计

在 `luasrc/view/xc/core.htm` 的核心管理内容下增加“资源更新”区域，包含三行：

1. Xray 核心：源选择、当前状态、更新按钮。
2. GeoIP：源选择、当前状态、更新按钮。
3. GeoSite：源选择、当前状态、更新按钮。

源选择只渲染后端返回的固定源 ID 和显示名，前端不能提交任意 URL。更新按钮只锁定当前行，显示下载结果，并刷新核心状态。页面不新增 URL 文本输入框，也不增加独立的自定义配置页。

Xray 更新只负责下载并安装到现有受管核心目录，不自动激活；激活仍由现有核心版本列表中的“Activate”操作完成。GeoIP/GeoSite 更新只负责下载并替换受管资源文件，不自动修改节点配置。

## 固定源与配置

新增 `xc.assetmanager` 维护资源类型、固定源表、架构模板和目标文件映射。源表中的 URL 模板由代码固定，支持官方源和项目选定的镜像源；只有经过白名单映射的资源类型、源 ID、版本和设备架构可参与 URL 展开。

UCI 只保存每种资源当前选择的源 ID，不保存 URL：

- `xray_update_source`
- `geoip_update_source`
- `geosite_update_source`

缺省源 ID 为 `official`。源 ID 无效时回退到 `official`，不会执行用户提交的任意地址。

## 下载、替换与回滚

- 控制器新增一个仅 POST 的资源更新 action，参数只有资源类型和固定源 ID。
- 平台适配器使用固定参数执行下载，写入受保护的临时文件；下载失败或临时文件写入失败时不改变当前资源。
- 下载成功后直接进行原子替换，不做 ELF、格式、版本、哈希或 Xray `run -test` 校验。
- 替换前，如果默认快照尚不存在，则把当前资源复制到默认快照目录；默认快照一旦建立不再覆盖。
- Geo 文件放入插件受管资源目录，资源目录优先于系统包目录；系统 `/usr/share/xray` 和 `/usr/share/v2ray` 文件不直接覆盖。
- 回滚操作从默认快照恢复对应资源；无快照时返回稳定错误，不删除当前文件。
- 更新和回滚记录资源类型、源 ID、结果和错误码，不记录 URL、下载内容或凭据。

由于本需求明确取消内容校验，更新成功只代表下载和文件替换成功；页面提示用户在需要时手动重启/激活并观察运行状态。

## 兼容与安全边界

- Lua 5.1、OpenWrt 21.02–24.10 继续支持。
- 只允许固定下载源和固定受管路径；下载超时、响应大小和临时文件权限仍受限制，这些是传输和文件安全边界，不属于内容校验。
- 不覆盖 `/usr/bin/xray`、系统包资源文件或现有核心回滚标记。
- Xray 版本上限 `26.6.27` 的现有手动核心策略保持不变；更新入口不自动激活高版本核心。

## 验证

- Lua 测试覆盖源白名单、默认源回退、一次性默认快照、直接替换和默认快照回滚。
- 控制器测试覆盖 POST-only、资源类型/源 ID 白名单和不接受 URL 参数。
- 核心页 UI 测试覆盖三种独立更新入口、源选择控件、不存在自定义 URL 输入框和更新状态刷新。
- 完整 `tests/run-host.sh`、`scripts/check-package.sh` 和 `git diff --check` 通过后再提交推送。
