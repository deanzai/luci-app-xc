# XC 后续功能设计

## 范围

本轮以 `fast_select_api` 为开发主线，覆盖核心上传体验、运行状态展示、插件版本显示、Geo/Xray 资源更新和访问控制。已有节点快速切换接口不改协议，只复用现有运行时事务、候选配置和回滚机制。

## 设计决定

### 核心上传

- 页面删除 SHA-256 输入框、核心版本列表中的 SHA-256 展示和备注输入/展示。
- 后台继续自动计算 SHA-256，用于完整性验证、版本 ID 和防篡改检查；用户不再提交期望哈希。
- 备注不再接收、不写入 manifest；上传采用 `XMLHttpRequest.upload.onprogress` 显示百分比和已上传字节。

### 状态与版本

- “运行中”状态使用不换行样式，避免状态列被拆成两行。
- 新增 `xc.version`，从 Makefile 的插件版本发布值维护显示版本；设置页运行状态区域显示该版本。

### Geo/Xray 资源

- 内置资源和 Xray 核心最高以 `26.6.27` 为版本门槛。
- 资源更新保留系统已有文件作为运行来源；更高版本不自动替换，只显示“可手动替换”的文字提示。
- 资源/核心替换必须经过文件类型、架构、版本和配置校验；失败不写入生效位置。

### 访问控制与 A/B 配置

- 新增访问控制页签，配置 DNS、域名/IP 直连规则和域名/IP 代理规则。
- 用户编辑内容先生成候选 Xray 配置，校验通过后才进入现有运行时事务。
- 原始配置/当前已生效配置作为不可覆盖的回滚基线；候选配置独立写入，类似 `boot_a` / `boot_b`。
- 校验失败只显示稳定错误码和提示，不替换候选、不重启、不提交 UCI；当前配置和回滚基线保持不变。

## 验收

- 上传过程中进度条随真实 `loaded/total` 更新，结束或失败后正确复位。
- 核心页源码和请求不再包含用户 SHA-256/备注字段，但核心管理单元测试仍覆盖后台自动哈希校验。
- 状态“运行中”不发生换行，设置页能显示插件版本。
- 访问控制能生成 DNS、direct/proxy 规则；非法规则校验失败时 Xray 不被调用且当前配置不变。
- 主机测试、包检查、设备部署和设备上的 `xray run -test` 全部通过。
