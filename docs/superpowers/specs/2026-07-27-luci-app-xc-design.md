# luci-app-xc 设计说明

## 目标

开发一个独立的 Xray 节点管理与切换 LuCI 插件，正式接管现有 `/usr/bin/xc` 和 `xc-xray` 服务的职责。现有 `xc` 仅作为需求原型和迁移来源；新插件采用 SSR Plus 的 LuCI、UCI、procd 与节点探测模式重新设计。

首版支持 OpenWrt/ImmortalWrt 21.02–24.10，使用 Xray Core，不引入 sing-box，不提供透明代理或订阅管理。插件只维护路由器上的 SOCKS 与 HTTP 代理入口。

## 包与系统架构

- GitHub 公开仓库与 OpenWrt 包名为 `deanzai/luci-app-xc`，采用 GPL-3.0。
- 菜单入口为“服务 → Xray 节点切换”。LuCI 使用传统 Lua controller、CBI 与 HTML 模板，并依赖 `luci-compat` 兼容 21.02–24.10。
- `/etc/config/xc` 是唯一持久配置源，包含一个全局 section 和多个节点 section；该文件声明为 conffile，升级时不得覆盖。
- 新的 `/etc/init.d/xc` procd 服务负责根据 UCI 生成 `/var/etc/xc/config.json`、调用 `xray run -test` 校验，并以前台进程方式托管 Xray；接管成功后停用旧 `/etc/init.d/xc-xray`。
- `/usr/bin/xc` 保留为兼容 CLI，所有操作与 LuCI 共用 UCI 数据和相同的生成、切换、探测及回滚逻辑。
- 包依赖 Xray Core、Lua/LuCI JSON 支持、`luci-compat`、`curl` 和运行所需的基础证书组件；不依赖 sing-box、Mihomo 或 SSR Plus。

## 配置模型

全局配置保存：

- 插件启停状态、当前主节点 section ID；
- 监听方式、SOCKS 端口（默认 `7890`）和 HTTP 端口（默认 `10809`）；
- 快速测速并发数（范围 `1–5`，默认 `3`）、连接超时、测速 URL；
- 切换后的出口健康检查 URL 与健康检查超时。

新安装默认解析并绑定 `network.lan` 当前 IPv4；无法解析时退回 `127.0.0.1` 并在界面报警。LAN 地址变化时由 hotplug 触发配置重建和服务重启。首版不配置透明代理、防火墙转发或按设备分流。

每个节点使用独立 UCI section，包含启用状态、显示名称、协议、服务器地址、端口以及协议所需的凭据、传输层和安全字段：

- VLESS、VMess、Trojan、Shadowsocks、SOCKS 使用结构化字段；
- Xray 支持但没有结构化表单的协议使用完整 outbound JSON；
- Xray 不原生支持的上游由用户以 SOCKS 节点接入；
- UUID、密码、密钥等敏感字段不在列表和普通接口响应中返回，编辑页默认掩码显示。

只有一个已启用节点时自动将其设为主节点。存在多个节点时由用户手工切换。所有流量统一走当前主节点；首版不保留原脚本的 `reality_uk_id` 或特殊域名专用节点。

## LuCI 界面

### 基本设置

- 插件启停、当前主节点、监听地址、SOCKS/HTTP 端口；
- 测速并发数、连接超时、测速 URL、出口健康检查 URL；
- Xray 运行状态、当前节点、监听状态和当前出口 IP；
- 保存应用、重启服务、测试当前节点和手动回滚操作。

### 节点管理

- 表格显示启用状态、当前节点标记、名称、协议、服务器、端口、连通状态、延迟与最后测速时间；
- 每行提供切换、单节点测速、编辑和删除；表头提供全部测速、停止测速、导入和添加节点；
- 删除当前节点前必须先选择替代节点；仅剩一个节点时禁止删除当前节点，除非用户先停用插件；
- 协议编辑页按类型动态展示字段，并提供高级 outbound JSON 编辑入口；
- 导入支持旧版 `nodes.json`、文件上传、批量粘贴 `vless://`、`vmess://`、`trojan://`、`ss://`、`socks://`/`socks5://` 分享链接，以及单个 outbound JSON；
- 导入先解析并预览，用户确认后一次性写入。重复项以协议、服务器、端口和身份字段的稳定指纹识别，默认跳过并报告结果。

### 运行日志

- 展示配置生成、校验、服务启动、切换、出口健康检查和自动回滚日志；
- 支持手动刷新和清空；日志不得记录完整分享链接、UUID、密码、密钥或完整 outbound JSON。

## 快速测速

测速复用 SSR Plus 的轻量探测方法，不为每个节点启动临时 Xray：

- LuCI controller 按节点 section ID 从 UCI 读取目标，不接受浏览器直接拼接的 shell 参数；
- TCP 类型优先做带超时的 socket 连接，并按传输和 TLS 配置尝试 TLS/WS 握手；必要时使用 TCP connect、ICMP 等回退方式计算延迟；
- SOCKS 上游的快速测速仅测试其端口连通与握手延迟，不发送节点凭据到浏览器；
- 单节点与全部测速调用相同接口。全部测速由前端任务队列控制并发，配置范围 `1–5`，默认 `3`，可停止后续排队任务；
- 返回端口可达状态、延迟毫秒值和测试时间，结果缓存到 `/tmp/xc-probe-cache.json`，不写入持久配置；
- 快速测速仅代表服务器连通性/握手延迟。完整代理可用性在实际切换时验证。

## 安全切换与回滚

1. LuCI 或 CLI 以节点 section ID 请求切换；后台加互斥锁，重复请求返回“操作进行中”。
2. 后台读取候选节点并生成临时 Xray 配置，执行 `xray run -test`。
3. 校验通过后保存当前运行配置和主节点状态，原子替换运行配置并重启 procd 服务。
4. 等待 SOCKS/HTTP 监听端口就绪，再分别通过两个入口请求健康检查 URL；两者都成功才提交新的 UCI 主节点。
5. 任一步失败时恢复旧运行配置、旧主节点和旧服务；无可用旧配置时停止服务并返回明确错误。
6. 手动回滚使用最近一次成功切换前的快照。快照仅保存一代，存于 `/etc/xc/rollback/` 并限制权限，不暴露给 LuCI 下载接口。

生成配置、切换、导入和迁移均使用临时文件加原子重命名。所有外部参数必须经白名单校验或 shell quoting；controller 不提供任意命令执行能力。

## 迁移与接管

- 首次安装识别现有 `/etc/xc/nodes.json`、`current`、`config.json`、`/usr/bin/xc` 和 `/etc/init.d/xc-xray`；
- 包的 `preinst` 在文件解包覆盖前，将旧脚本、旧服务和旧配置复制到 `/etc/xc/legacy-backup-<timestamp>/`；后续迁移只读取该快照并将节点与当前节点转换为 UCI，敏感文件权限保持为仅 root 可读；
- 迁移先生成候选 UCI 和 Xray 配置并执行校验，全部成功后才停用旧服务并启用新服务；迁移失败时保留旧服务运行且不接管；
- 包升级保留 `/etc/config/xc`、迁移备份和回滚快照；卸载默认保留配置，用户可手工删除。

## 错误处理

- 无节点、主节点缺失、端口冲突、非法协议字段、JSON 解析失败和 Xray 校验失败均阻止启动并在界面给出具体原因；
- 导入是全有或全无的事务：解析错误不会写入部分节点；重复项与跳过原因在预览和结果中列出；
- 节点切换期间禁用相关按钮；页面刷新后通过状态接口恢复操作状态；
- 测速停止只取消尚未开始的前端任务，已发送的轻量请求允许在短超时内结束；
- 任何日志或错误响应都必须脱敏。

## 测试与验收

### 自动化测试

- 配置生成：各结构化协议、TLS/Reality、传输层、SOCKS 上游和高级 outbound JSON；
- 输入校验：端口范围、UUID、地址、必填字段、非法 JSON、未知 section ID 与命令注入字符串；
- 导入：旧 `nodes.json`、各分享链接、outbound JSON、重复检测、混合有效/无效输入的原子失败；
- 状态机：单节点自动选择、多节点切换、删除保护、配置校验失败、监听超时、健康检查失败与成功回滚；
- 测速：单节点、并发 `1/3/5`、超时、不可达节点、停止排队和缓存更新；
- 迁移：成功接管、失败保持旧服务、重复运行迁移幂等、升级保留配置。

### 设备验收

- 在当前 ImmortalWrt 24.10/aarch64 路由器上安装包，迁移 11 个现有节点并验证旧节点数据未丢失；
- 验证节点 CRUD、导入预览、快速测速、主节点切换、SOCKS `7890`、HTTP `10809`、出口 IP 和失败自动回滚；
- 使用 OpenWrt 21.02 与 24.10 SDK 分别完成包构建，检查 Lua/CBI、procd、hotplug 和依赖兼容性；
- README 提供 feed、源码包和 SDK 编译安装方式，以及升级、备份、恢复和故障排查说明。
