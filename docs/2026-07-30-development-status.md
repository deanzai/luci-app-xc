# luci-app-xc 开发状态总结

更新时间：2026-07-30

项目仓库：`deanzai/luci-app-xc`

## 1. 项目定位

`luci-app-xc` 是面向 OpenWrt/ImmortalWrt 的 Xray 节点管理与切换插件，用于接替原有 `xc` 切换脚本。当前版本只管理本地 SOCKS/HTTP Xray 监听器和自建节点，不承担透明代理、订阅管理或复杂分流。

最低兼容目标为 OpenWrt 21.02；当前设备验收环境为 ImmortalWrt 24.10、LuCI 24.10、Argon 主题。

## 2. 已完成的功能

### 2.1 插件与服务框架

- 已建立标准 LuCI 插件目录、Makefile、ACL、UCI 配置、init 脚本、hotplug 脚本和 uci-defaults。
- 已实现 procd 管理的 XC/Xray 服务生命周期。
- 已实现旧 `xc-xray` 服务停止、禁用和新 XC 服务接管流程。
- 已实现安装前备份、旧配置迁移、失败恢复和幂等安装脚本。
- `/etc/config/xc` 和运行目录使用受限权限，节点凭据不会写入日志或安装包。

### 2.2 节点管理

- 支持新增、编辑、删除自建节点。
- 支持本地导入预览、确认导入和去重，不包含订阅功能。
- 支持单节点时自动使用该节点，多节点时由用户选择活动节点。
- 节点列表已显示名称、协议、服务器、端口、延迟和操作按钮。
- `测速 / 切换 / 编辑 / 删除` 已在同一操作行展示。
- 当前活动节点直接整行高亮，不再使用独立“当前”列；切换不刷新整个页面。
- `新增 / 全部测速 / 停止测速` 已合并到节点页顶部同一工具栏。
- 支持单节点测速、全部测速和停止测速。
- 全部测速使用可配置并发数 `1-5`，默认值为 `3`。
- 测速结果使用缓存并直接更新节点列表的“延迟”列。

### 2.3 Xray 协议与配置生成

- 使用 Xray 内核，不使用 sing-box。
- 已支持结构化 VLESS、VMess、Trojan、Shadowsocks 和 SOCKS5 节点。
- 已支持 VLESS Reality/TLS、TCP、WebSocket 和 gRPC 等已列入兼容白名单的组合。
- 其他 Xray 支持但未结构化建模的协议，可通过受校验的原始 Xray outbound JSON 接入。
- 已支持无认证或带认证的本地 SOCKS/HTTP 监听器。
- 当前所有流量统一使用一个活动节点。
- Xray access log 保持关闭，DNS log 保持关闭。
- Xray 内核运行日志级别支持 `错误 / 警告 / 信息 / 调试`，默认“警告”。

### 2.4 节点切换与可靠性

- 已实现候选配置生成、Xray 配置校验、服务重启、监听器检查和健康检查。
- 已实现活动节点 UCI 提交、事务日志、回滚快照、异常恢复和并发锁。
- 已实现切换失败时恢复原配置，避免把不健康候选配置直接留在运行状态。
- 已修复设备验收发现的两个兼容问题：
  - Xray 候选配置固定使用 `.json` 后缀，避免 Xray 25.2.21 无法识别配置格式。
  - OpenWrt nixio 目录同步不再使用设备不支持的 `O_DIRECTORY` 组合，改为 `O_NOFOLLOW` 打开并通过文件描述符确认目录类型。
- 修复后的替换包版本已提升为 `0.1.0-r4`。

### 2.5 状态页与 Exit IP

- 状态页显示服务状态、活动节点、本地 SOCKS/HTTP 地址、监听状态和 Exit IP。
- Exit IP 通过本地代理出口探测，不暴露 curl 原始响应。
- Exit IP 使用独立 5 秒超时。
- Exit IP 使用按节点键控的 60 秒私有缓存，避免 LuCI 轮询反复请求公网检测地址。
- 节点不匹配、缓存过期、IP 非法、切换竞态或服务异常时均不会复用旧 Exit IP。

### 2.6 日志功能

- 日志页合并显示 XC 插件日志和 Xray 内核运行日志。
- 支持 `全部 / 错误 / 警告 / 信息 / 调试` 五种界面筛选。
- XC 日志覆盖启动、停止、渲染、切换、测速、导入、回滚及失败事件。
- 日志读取有大小和条数限制，并对 UUID、密码、Token、URI、Authorization、原始 JSON 等敏感内容脱敏。
- 日志使用 DOM 文本节点渲染，避免日志内容被当作 HTML 或脚本执行。
- 已修复空日志数组被编码为 `{}` 的问题；无匹配记录时显示“（空）”。
- “清空日志”只清除 XC 私有日志，保留 Xray/OpenWrt 系统日志，并显示准确提示。
- 设备复测中，清空前为 39 条 XC、46 条 Xray；清空后 XC 为 0、Xray 仍为 46。
- Xray 日志级别控制后台新日志的产生量，日志页筛选只控制现有日志的显示范围。

### 2.7 中文界面与兼容性

- 设置、节点、状态和日志界面均已提供完整简体中文翻译。
- POT/PO 目录当前包含 123 个唯一翻译条目，并生成 `xc.zh-cn.lmo`。
- 已兼容 LuCI legacy CBI 和 LuCI 24.10 ucode bridge。
- 已修复控制器中 `call()` 全局函数在新 LuCI 上不存在的问题。
- 已移除 LuCI 24.10 legacy CBI 不支持的 `url` datatype，改用 HTTP/HTTPS 自定义校验。
- CI/主机检查覆盖 OpenWrt 21.02 和 24.10 构建矩阵。

### 2.8 测试与安全

- Lua 5.1 主机测试覆盖生成器、运行时、事务、回滚、迁移、日志、导入、测速、平台适配和控制器。
- Node 测试覆盖节点列表、测速队列、日志 DOM/XHR 和状态页行为。
- 包检查覆盖文件布局、权限、脚本语法、翻译、LMO、敏感信息和构建工作流。
- 最近一次完整主机验证通过 272 个 Lua 测试以及全部 Node、翻译、LMO 和包检查。
- 独立代码质量审查未发现 Critical 问题；审查要求的普通文件拒绝测试已补入当前工作树。

## 5. 当前明确不开发的功能

这些功能不是遗漏，而是用户已明确排除或安排到后续阶段：

- 透明代理、防火墙规则、TProxy/REDIRECT 接管。
- 节点订阅、定时订阅更新和远程订阅源管理。
- sing-box 内核支持。
- 按设备、域名、应用或流量类型选择不同专用节点。
- 负载均衡、自动故障转移和基于延迟的自动选优。
- Xray access log；当前只接入低隐私风险的运行日志。
- 日志导出、远程上传、长期归档、图表统计和全文搜索。
- 节点测速历史趋势图和定时后台测速。
- GitHub Release、软件源仓库索引和在线自动升级。

## 6. 后续建议开发顺序

### 第一阶段：完成当前版本收尾

1. 完成最终代码审查并提交 r4 改动。
2. 清理设备上传 IPK 和临时 SSH 凭据，保留配置备份。
3. 通过指定代理推送 GitHub。

### 第二阶段：增强单节点模式体验

1. 增加节点连通性定时检测和可选自动故障转移。
2. 增加测速时间、最近成功时间和失败原因的简洁展示。
3. 增加配置导出和恢复功能，但默认继续对凭据做保护。

### 第三阶段：可选高级能力

1. 按用途设置专用节点。
2. 增加策略路由或透明代理，但应作为独立设计阶段处理。
3. 增加软件源发布、GitHub Release 和可重复构建产物。

## 7. 当前结论

核心目标已经实现：XC 已从单一切换脚本发展为可安装的 LuCI 插件，具备自建节点管理、测速、选择、Xray 配置生成、服务接管、事务切换、回滚、状态、Exit IP、统一脱敏日志和完整中文界面。

当前剩余工作主要是 r4 的最终提交、临时凭据清理和推送，不是新的核心功能开发。透明代理、订阅、sing-box 和多策略专用节点仍按既定范围留待以后决定。
